Official versioned architecture document for the standalone native Android application. Defines Clean Architecture layer boundaries, diurnal swing clothing calculation, zero-backend Open-Meteo integration, and battery-compliant morning scheduling.

1. System Overview & Core Capabilities

SMO-ARCH-SPEC v1.0.0

ShowMeOutfit is designed as a zero-backend, standalone native Android application that prescribes daily attire and essential gear based on comprehensive daytime weather metrics.

⏰ Mode 1: Scheduled Morning Alert

Exact wake-up notification (configured by user, e.g. 07:00 AM) using AlarmManager + WorkManager with glanceable outfit layers and urgent accessory alerts.

📱 Mode 2: Interactive On-Demand

Jetpack Compose interactive UI providing diurnal hourly timelines, UV and rain probabilities, and manual city search fallback.

🛡️ Standalone & Zero-Backend

Direct connection to Open-Meteo REST API (zero client API key leakage risk); Room DB caching with 3-hour freshness.

3. Diurnal Outfit Recommendation Algorithm

All-Day Intelligence

The recommendation engine evaluates the full daylight spectrum (07:00 – 22:00) rather than a single morning snapshot. It identifies diurnal temperature swings ($\Delta T = T_{\max} - T_{\min} \ge 7^\circ\text{C}$), rain spikes ($P_{\text{rain}} \ge 35\%$), and UV levels. 

flowchart TD
    Start["Fetch Hourly Forecast: 07:00 - 22:00"] --> AdjustTemp["Apply Thermal Sensitivity Offset: T_eff = T + Offset"]
    AdjustTemp --> CalcMetrics["Calculate: T_min, T_max, Delta-T = T_max - T_min, Max_Precip_Prob, Max_UV, Max_Wind"]
    
    CalcMetrics --> EvalBase["Evaluate Base & Bottoms: Based on T_max & T_avg"]
    CalcMetrics --> EvalLayers["Evaluate Layering: If Delta-T >= 7°C or T_min < 14°C"]
    
    EvalLayers --> LayerDecision{"Delta-T >= 7°C?"}
    LayerDecision -- Yes --> AddMidLayer["Add Removable Mid/Outer Layer: Cardigan, Light Jacket, or Hoodie"]
    LayerDecision -- No --> DirectOuter["Evaluate Standard Outer Layer based on T_max"]

    AddMidLayer --> EvalPrecip
    DirectOuter --> EvalPrecip

    EvalPrecip{"Max Precip Prob >= 35% or Rain Code?"}
    EvalPrecip -- Yes --> AddUmbrella["Add Accessory: Umbrella / Raincoat + Waterproof Footwear"]
    EvalPrecip -- No --> CheckUV

    AddUmbrella --> CheckUV
    CheckUV{"Max UV Index >= 3.0?"}
    CheckUV -- Yes --> AddSunProtection["Add Accessory: Sunglasses + Sunscreen (if UV >= 6: Sun Hat)"]
    CheckUV -- No --> CheckWind

    AddSunProtection --> CheckWind
    CheckWind{"Max Wind >= 35 km/h?"}
    CheckWind -- Yes --> AddWindbreaker["Upgrade Outer Layer to Windbreaker"]

4. Technical Stack Decision Matrix

Trade-off Analysis
Component Selected Stack Alternative Pros & Advantages Cons & Trade-offs
UI Framework Jetpack Compose (Material 3) XML Views Declarative state modeling, frictionless animations, modern dynamic theming. Slightly higher initial clean compilation overhead.
Dependency Injection Koin 4.x Hilt / Dagger Pure Kotlin DSL, zero KSP/kapt annotation processing overhead, rapid builds. Runtime graph resolution rather than compile-time verification.
Weather Provider Open-Meteo REST API OpenWeatherMap No API key required (eliminates client secret leakage), free, hourly metrics. 10,000 calls/day per IP rate limit (ample for client app).
Networking Ktor Client 3.x Retrofit + OkHttp Multiplatform coroutines, lightweight footprint, Kotlinx.serialization integration. Slightly different configuration syntax than traditional Retrofit.
Persistence Room DB + DataStore SharedPreferences Type-safe SQLite with Flow observation; DataStore provides transactional writes. Schema migration planning required for future structural changes.
Morning Trigger AlarmManager + WorkManager Periodic WorkManager Guaranteed exact wake-up even in deep Doze mode; reliable network retry backoff. Requires Android 12+ SCHEDULE_EXACT_ALARM handling.

6. Offline-First Caching Strategy

Resilience

Because ShowMeOutfit is a standalone client with no intermediate proxy:

  • Local Cache Persistence: Every fetched weather forecast snapshot is saved to Room DB with a millisecond timestamp.
  • Freshness TTL: Snapshots are fresh for 3 hours. If offline within 12 hours, cached data generates the recommendation with an indicator.
  • Location Coordinates: Last resolved GPS coordinates are preserved in DataStore, eliminating timeout delays during background execution.
